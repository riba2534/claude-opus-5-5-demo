# 豆包炫舞 · Doubao Dance

敲方向键、踩重拍，和 Q 版豆包一起在舞台上赢下三位对手——一个 3D 节奏舞蹈游戏。
由 Claude Fable 5.2 在 Claude Code 中单会话生成，源码零人工改动。

**在线体验：<https://fable-5-2-doubao-dance.riba2534.cn/>**

整个游戏是一个约 700 KB 的单文件 HTML（gzip 后约 190 KB），游戏本身不请求任何外部资源
（自定义域名上 Cloudflare 会自动注入它自己的 Web Analytics 脚本，不属于游戏文件）：
没有图片、没有模型文件、没有音频文件，角色、舞台、表情贴图、三首曲子和所有音效都是代码现场生成的。

「这种技术栈」指同一会话前两轮里拆解过的一个单文件 3D 网页游戏：Three.js 做渲染底座，资源全部程序化生成，画面质感靠光照和后处理，音频用 Web Audio 实时合成。

## 玩法

三种玩法，三首曲子，三档难度，每局和三位 AI 对手同台比分。

| 玩法 | 规则 |
| --- | --- |
| 舞步 | 每个小节给一串方向键，按顺序敲完，等节拍圈缩到和目标圈重合（第 4 拍）时按空格。敲错从头再来；带「反」字的红色箭头要按相反方向 |
| 节拍 | 四条轨道的音符顺着轨道落下，到判定线时按对应方向。谱面由每首歌的主旋律生成 |
| 炫舞秀 | 主歌拼舞步，副歌打节拍，间奏自由发挥，最后以终结技收尾 |

- **判定**：按时间差分 Perfect / Great / Cool / Bad / Miss 五档。舞步的等级越高序列越长，得分倍率也越高；连续 Perfect 有连 P 加成
- **灵感爆发**：Perfect 和 Great 会积攒灵感值，攒满后在下一小节自动爆发，持续 4 小节，期间得分 ×2，舞台变成彩虹配色并喷出火花
- **自由发挥**：间奏没有谱面，踩着拍子按任意方向键，豆包会摆出对应造型，踩得准有小分
- **终结技**：全曲最后一串是跨两小节的长序列，得分 ×3，打完全场定格、放烟花
- **对手**：奶黄、抹茶、芝麻三位原创角色，各有固定的水平，实时排名显示在右上角
- **豆包的气泡**：对局中豆包会根据连击、失误、名次变化说话，结算时按评级给一句点评

| 操作 | 键盘 | 触屏 | 手柄 |
| --- | --- | --- | --- |
| 方向 | ← ↓ ↑ → 或 W A S D（节拍玩法也可用 D F J K） | 屏幕左下的方向键；节拍玩法直接点四条轨道 | 十字键 |
| 踩拍 | 空格 / 回车 | 右下的圆环 | A / B / X / Y |
| 暂停 | Esc / P | 右上角按钮 | Start |

设置里可以调音乐和音效音量、判定偏移（蓝牙耳机延迟大时用）和画质。

## 技术

| 方面 | 做法 |
| --- | --- |
| 渲染底座 | Three.js r186（esbuild 打包内联），HDR 半浮点渲染目标 + MSAA |
| 角色 | 约 3.5 头身的 Q 版人偶：17 个关节的 Object3D 骨架，身体由椭球、胶囊、旋转体、圆环拼装；卡通渐变着色 + 背面外扩描边 + 随舞台变色的轮廓光 |
| 表情 | 脸是贴在头部球面上的一块曲面，六种表情（微笑、眨眼、开心、惊喜、失误、wink）用 Canvas 2D 现画成贴图，按判定和动作切换 |
| 舞蹈 | 姿势用语义参数书写（手臂的仰角、方位角、手肘弯曲方向，腿的前抬、外展、屈膝），转成四元数关键帧后按节拍插值；过渡集中在拍点前完成，让造型落在拍子上；再叠加每拍屈膝的律动和脚底贴地修正。共 15 个循环动作，加上终结造型、踉跄和 3 个自由造型，全部带镜像版本 |
| 二级运动 | 鬓发、马尾、裙摆、兜帽各挂一个弹簧阻尼器，由父关节的世界速度驱动 |
| 舞台 | LED 地板、弧形点阵大屏、穹顶各是一个着色器；地板叠加平面镜面反射（Reflector 配自定义着色器）；10 盏摇头灯的体积光束、12 道激光、霓虹环、音箱都跟节拍联动；大屏上的频谱柱读的是 AnalyserNode 的实时数据 |
| 观众与粒子 | 观众和荧光棒用 InstancedMesh，每帧在 CPU 上更新；粒子是一个 1600 上限的环形缓冲，承担命中火花、彩带、烟花和喷泉 |
| 后处理 | EffectComposer：Bloom → 自定义终段（色差、暗角、闪白）→ 色调映射输出。镜头按段落自动切机位，副歌用硬切 |
| 音频 | 纯 Web Audio 合成：底鼓、军鼓、拍手、踩镲、贝斯、铺底、和弦切音、主音、拨弦、FM 钟声；底鼓触发侧链压缩；卷积混响的脉冲响应是生成的噪声；主音走节拍延迟 |
| 节拍时钟 | 以 `AudioContext.getOutputTimestamp()` 给出的「已经播出去的采样时间」为准，做小误差平滑；按键时间戳换算回这条时间轴再判定。没有声音时退回性能时钟 |
| HUD | 序列方块、节拍环、音符轨道、判定字都画在一张 2D Canvas 上；触屏的按键位置和命中测试共用同一份布局数据 |
| 自适应 | 三档画质按设备自动选择，运行中按帧率动态调整渲染分辨率；竖屏自动放宽视角并换成触屏布局 |

## 本地构建

```bash
cd doubao-dance
npm install
node build.mjs          # 输出 dist/index.html，直接用浏览器打开即可
node build.mjs --dev    # 不压缩，方便调试
```

部署用的是 Cloudflare Workers 静态资源，配置在 `wrangler.jsonc`：设置好 `CLOUDFLARE_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID` 后执行 `npm run deploy`。

调试用的 URL 参数：`?auto=1` 自动演奏，`?song=cream|neon|spark`、`?mode=step|beat|show`、`?diff=easy|normal|hard` 直接开局，`?q=low|medium|high` 指定画质，`?mute=1` 静音。

## 自测

交付前模型自己做过的验证，脚本都在 `test/` 下：

- **逻辑模拟**（`sim.mjs`，不需要浏览器）：用假时钟把 3 首歌 × 3 种玩法 × 3 档难度各自动演奏两遍，检查谱面合法性、判定次数与谱面一致、满技能自动演奏全 Perfect 且评级 SS
- **流程**（`flow.mjs`，无头 Chromium + 真实 AudioContext）：模拟点击和按键走完 标题 → 选歌 → 开局 → 手动打三回合 → 敲错键 → 暂停 → 继续 → 重开 → 返回选歌，确认每一步状态正确、无报错
- **音频离线渲染**（`audio.mjs`）：用 OfflineAudioContext 把三首歌完整渲染出来，按段落统计峰值、响度和高低频能量占比。结果是全曲峰值不超过 0.92、无削波、无 NaN；据此把一开始偏闷的混音重新平衡过一次
- **姿势检查表**（`poses.mjs`）：冻结节拍，把每个动作在各拍点的样子截图拼表。靠它发现并修掉了刘海盖住眼睛、手臂太短举不过头、手肘弯曲方向不对等问题
- **画面**（`shot.mjs`）：在 1280×720、960×540、390×844 触屏竖屏下对标题、选歌、三种玩法、灵感爆发、终结技、结算分别截图检查

没有覆盖到的：无头环境用的是软件渲染，真实显卡上的帧率没有实测；曲子只做了数值层面的检查，没有人耳试听；手机只验证了模拟的触屏视口，没有在真机上跑。
