# 豆包炫舞 · Doubao Dance

敲方向键、踩重拍，和豆包一起在舞台上赢下三位对手——一个 3D 节奏舞蹈游戏。
由 Claude Fable 5.2 在 Claude Code 中生成，源码零人工改动。

**在线体验：<https://fable-5-2-doubao-dance.riba2534.cn/>**

整个游戏是一个约 780 KB 的单文件 HTML（gzip 后约 245 KB），游戏本身不请求任何外部资源
（自定义域名上 Cloudflare 会自动注入它自己的 Web Analytics 脚本，不属于游戏文件）。
唯一的外部素材是豆包的头：取自豆包官方应用图标，处理后以 35 KB 的 WebP 内联在文件里。
身体、对手、舞台、三首曲子和所有音效都是代码现场生成的。

## 提示词原文

第一轮：

> 需要使用这种技术栈创建一个新的游戏, 你去搜索一下字节跳动的豆包，获取它的角色, 你再去搜索一下 QQ 炫舞、劲舞团这两款游戏的玩法, 我要创造一个游戏 叫做 《豆包炫舞》, 你直接帮我在当前仓库上实现, 实现完成之后提交并推送, 部署在我的 Cloudflare 上, 域使用 fable-5-2-doubao-dance.riba2534.cn

「这种技术栈」指同一会话前两轮里拆解过的一个单文件 3D 网页游戏：Three.js 做渲染底座，资源程序化生成，画面质感靠光照和后处理，音频用 Web Audio 实时合成。

第二轮（第一版上线后）：

> 我需要你派出多个 Agent 继续 review 一下 我需要真实的豆包贴图模型 继续迭代：我允许你使用外部的模型和贴图资源 我需要官方版豆包的长相，而不是你生成的这个完全不像的东西
> 迭代完成直接上线

第一版的豆包是模型照着"短发、粗眉"的文字描述自己画的，不像。第二轮做了两件事：把豆包换成官方长相，以及按五个审查代理的结论修问题，详见下面两节。

## 豆包的形象从哪来

| 部位 | 来源 | 做法 |
| --- | --- | --- |
| 头（脸、发型） | 豆包官方应用图标，App Store 上 `com.bot.doubao` 的 1024 px 版本 | `tools/make_head.py` 按背景色和连通性抠掉浅蓝圆底，切到下巴，输出带透明通道的头部贴图；运行时按轮廓的距离场把它鼓成一个有厚度的浮雕头，正面是官方的脸，背面涂成从图里采样到的发色 |
| 表情 | 同一张图 | 官方只有一张静态正脸。闭眼和笑眼是脚本在原图上做的局部补丁：用周围肤色把眼睛抹平，再画一条睫毛弧线。眉毛、嘴、发型始终是官方原样 |
| 服装 | 官方 B 站账号视频里的常规造型 | 宽松黑色短袖 T 恤（领口露一圈白边）、深色卷边长裤、白色运动鞋，用几何体搭 |
| 身材比例 | 游戏自定 | 官方视频里约 5.5 头身；这里为了舞蹈动作在小屏上看得清，用的是 3 头身左右的 Q 版 |

## 玩法

三种玩法，三首曲子，三档难度，每局和三位 AI 对手同台比分。

| 玩法 | 规则 |
| --- | --- |
| 舞步 | 每个小节给一串方向键，按顺序敲完，等节拍圈缩到和目标圈重合（第 4 拍）时按空格。敲错从头再来；带「反」字的红色箭头要按相反方向 |
| 节拍 | 四条轨道的音符顺着轨道落下，到判定线时按对应方向。谱面由每首歌的主旋律生成 |
| 炫舞秀 | 主歌拼舞步，副歌打节拍，间奏自由发挥，最后以终结技收尾 |

- **判定**：按时间差分 Perfect / Great / Cool / Bad / Miss 五档。舞步序列没敲完但敲了一半以上、空格也踩在拍子附近，算 Bad，按完成比例给分
- **连 P 与连击**：舞步连续 Perfect 有倍率，断在 Great 上只掉一半；节拍的连击倍率 40 连封顶 ×1.5
- **灵感爆发**：Perfect 和 Great 会积攒灵感值，攒满后在下一个有谱面的小节自动爆发，持续 4 小节，期间得分 ×2
- **自由发挥**：间奏没有谱面，踩着拍子按任意方向键，豆包会摆出对应造型，踩得准有小分
- **终结技**：全曲最后一串是跨两小节的长序列，得分 ×3，打完全场定格、放烟花
- **对手**：奶黄、抹茶、芝麻三位原创角色，各有固定的水平，实时排名显示在右上角

| 操作 | 键盘 | 触屏 | 手柄 |
| --- | --- | --- | --- |
| 方向 | ← ↓ ↑ → ，或 W A S D，或 H J K L | 屏幕左下的方向键；节拍玩法直接点四条轨道 | 十字键 |
| 踩拍 | 空格 / 回车 | 右下的圆环 | A / B / X / Y |
| 暂停 | Esc / P | 右上角按钮 | Start |

暂停后继续会先倒数三下。设置里可以调音乐和音效音量、判定偏移（蓝牙耳机延迟大时用）和画质。

### 难度

舞步序列的长度按「每秒要敲几个键」封顶，所以同一档难度在快歌上序列更短：

| | 简单（约 2 键/秒） | 普通（约 3 键/秒） | 困难（约 4.5 键/秒） |
| --- | --- | --- | --- |
| 奶油心跳 104 BPM | 最长 3 键 | 5 键 | 8 键 |
| 霓虹豆浆 124 BPM | 3 键 | 4 键 | 7 键 |
| 灵感爆发 150 BPM | 2 键 | 3 键 | 5 键 |

终结技比上表再多 2 键。普通档偶尔出现反键，困难档反键更多。节拍玩法里，简单档只留整拍上的音，普通档跟主旋律的八分音符，困难档在伴奏有十六分音的位置再补音符并增加双押。

### 曲目

| 曲名 | 速度 | 调式 | 风格 | 时长 |
| --- | --- | --- | --- | --- |
| 奶油心跳 | 104 BPM | C 大调 | 轻快流行 | 102 秒 |
| 霓虹豆浆 | 124 BPM | A 小调 | 四拍踩满的迪斯科 | 101 秒 |
| 灵感爆发 | 150 BPM | E 小调 | 高速电音，带蓄力段 | 96 秒 |

三首都是为这个游戏写的原创曲，以 16 分音符步进的文本谱记在 `src/songs.js` 里，由音序器实时驱动合成器演奏。

## 技术

| 方面 | 做法 |
| --- | --- |
| 渲染底座 | Three.js r186（esbuild 打包内联），HDR 半浮点渲染目标 + MSAA |
| 豆包的头 | 官方头像贴图 + 运行时生成的浮雕网格：对贴图的 alpha 做距离变换得到有符号距离场，按到轮廓的距离给出圆角，再叠加一个椭球形的整体鼓起；正反两片在轮廓内侧一圈完全重合，侧面不露缝。贴图以预乘 alpha 上传，着色器里还原后手动转线性空间 |
| 身体与对手 | 17 个关节的 Object3D 骨架，身体由椭球、胶囊、旋转体、圆环拼装；卡通渐变着色 + 背面外扩描边 + 随舞台变色的轮廓光。三位对手的脸是 Canvas 2D 现画的表情贴图 |
| 舞蹈 | 姿势用语义参数书写（手臂的仰角、方位角、手肘弯曲方向，腿的前抬、外展、屈膝），转成四元数关键帧后按节拍插值；过渡集中在拍点前完成，让造型落在拍子上；再叠加每拍屈膝的律动和脚底贴地修正。共 15 个循环动作，加上终结造型、踉跄和 3 个自由造型，全部带镜像版本 |
| 舞台 | LED 地板、弧形点阵大屏、穹顶各是一个着色器；高画质下地板叠加平面镜面反射；10 盏摇头灯的体积光束、12 道激光、霓虹环、音箱都跟节拍联动；大屏上的频谱柱读的是 AnalyserNode 的实时数据 |
| 观众与粒子 | 观众和荧光棒用 InstancedMesh；粒子是一个环形缓冲，承担命中火花、彩带、烟花和喷泉 |
| 后处理 | EffectComposer：Bloom → 自定义终段（色差、暗角、闪白）→ 色调映射输出。镜头按段落自动切机位，副歌用硬切 |
| 音频 | 纯 Web Audio 合成：底鼓、军鼓、拍手、踩镲、贝斯、铺底、和弦切音、主音、拨弦、FM 钟声；底鼓触发侧链压缩；卷积混响的脉冲响应是生成的噪声。每首曲子用一套独立的节点，切歌时整体掐掉，长音不会拖到下一首 |
| 节拍时钟 | 以 `AudioContext.getOutputTimestamp()` 给出的「已经播出去的采样时间」为准，做小误差平滑，只向前走；按键时间戳换算回这条时间轴再判定。没有声音时退回性能时钟 |
| HUD | 序列方块、节拍环、音符轨道、判定字都画在一张 2D Canvas 上；触屏的按键位置和命中测试共用同一份布局数据，并避开刘海屏的安全区 |
| 自适应 | 三档画质按设备自动选择，运行中按帧率动态调整渲染分辨率；手机竖屏、手机横屏、竖屏平板各有对应的布局 |

## 审查与修复

第二轮派了五个代理并行工作，两个找素材（见上文），三个做审查。审查结论由主会话逐条核实后修复：

| 审查 | 方法 | 主要发现与处理 |
| --- | --- | --- |
| 代码缺陷 | 通读源码，用无头浏览器复现 | 12 条。光束着色器对负数做 `pow`，在部分显卡上会得到 NaN 并经泛光扩散成整屏黑（改为先夹到 0）；暂停菜单的按钮在等待音频恢复时可以重入，把状态搅乱（改为同步切状态并校验流程编号）；节拍玩法下 WASD 失效（去掉冲突的 DFJK，改用 HJKL）；切歌时上一首的长音叠进下一首；结算页出现瞬间空格会误触重开；菜单界面切到后台音乐不停 |
| 画面与布局 | 5 种视口下截图约 270 张 | 20 条。段落横幅盖住主角的脸（移到顶栏正下方并缩小）；画质自适应变档时黑一帧（改到下一帧开画前调整尺寸）；手机横屏下序列、判定字、横幅叠成一团，结算和选歌的主按钮在屏幕外（单独做了横屏布局）；竖屏平板套用了桌面布局；大屏上的曲名被点阵打碎；若干小字没有描边看不清 |
| 玩法数值 | 用真实判定引擎模拟不同水平的玩家，每个组合 200 局 | 序列长度不看歌曲速度，150 BPM 的简单档比 104 BPM 的困难档还难，普通玩家 9 个舞步组合里只打得了 1 个（改为按每秒键数封顶）；节拍玩法的普通档和困难档按键时刻完全相同（困难档补十六分音符）；对手在节拍玩法里比舞步玩法强一档（提高对手在音符上的失手率）；一次失误最多掉 20% 总分（连 P 减半、连击倍率封顶、未敲完按比例给分）；《灵感爆发》蓄力段的和弦让旋律成片地压在三全音上（改了一行和弦进行） |

数值调整后同一套模拟的结果（每个组合 200 局）：手速一般的玩家在简单档拿第一的概率是 62%–100%，普通档名次多在第二、垫底的概率不超过 5%；熟练玩家在普通档 65%–100% 拿第一，困难档 18%–96%。

## 本地构建

```bash
cd doubao-dance
npm install
node build.mjs          # 输出 dist/index.html，直接用浏览器打开即可
node build.mjs --dev    # 不压缩，方便调试
```

部署用的是 Cloudflare Workers 静态资源，配置在 `wrangler.jsonc`：设置好 `CLOUDFLARE_API_TOKEN` 和 `CLOUDFLARE_ACCOUNT_ID` 后执行 `npm run deploy`。

调试用的 URL 参数：`?auto=1` 自动演奏，`?song=cream|neon|spark`、`?mode=step|beat|show`、`?diff=easy|normal|hard` 直接开局，`?q=low|medium|high` 指定画质，`?mute=1` 静音。

## 自测

脚本都在 `test/` 下：

- **逻辑模拟**（`sim.mjs`，不需要浏览器）：用假时钟把 3 首歌 × 3 种玩法 × 3 档难度各自动演奏两遍，检查谱面合法性、判定次数与谱面一致、满技能自动演奏全 Perfect 且评级 SS
- **流程**（`flow.mjs`，无头 Chromium + 真实 AudioContext）：模拟点击和按键走完 标题 → 选歌 → 开局 → 手动打三回合 → 敲错键 → 暂停 → 继续（含倒数，以及倒数期间按 Esc）→ 重开的同时按 Esc → 返回选歌 → 节拍玩法下 WASD 与 HJKL 的键位，确认每一步状态正确、无报错
- **音频离线渲染**（`audio.mjs`）：用 OfflineAudioContext 把三首歌完整渲染出来，按段落统计峰值、响度和高低频能量占比，检查削波和 NaN
- **姿势检查表**（`poses.mjs`）：冻结节拍，把每个动作在各拍点的样子截图拼表
- **画面**（`shot.mjs`）：在桌面 720p、手机竖屏、手机横屏、竖屏平板几种视口下截图检查标题、选歌、对局、终结技、结算等画面；豆包的头另外从正面、侧面、背面六个角度检查接缝

没有覆盖到的：无头环境用的是软件渲染，真实显卡上的帧率和上面那条着色器 NaN 的修复效果都没有在真机上验证；曲子只做了数值和乐理层面的检查，没有人耳试听；手机只验证了模拟的触屏视口，没有在真机上跑；数值模拟里的"玩家水平"是假设的参数，不是真人数据。
