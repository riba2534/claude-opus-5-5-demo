# 豆包单车大作战 · Doubao Bike Blaster

骑着自行车的豆包，对抗满城乱窜的 Bug 和「幻觉」——一个第三人称 3D 单车枪战游戏。
由 Claude Fable 5.2 在 Claude Code 中单会话生成，源码零人工改动。

**在线体验：<https://fable-5-2-doubao.riba2534.cn/>**

整个游戏是一个约 877 KB 的单文件 HTML（gzip 后约 306 KB），运行时不请求任何外部资源
（自定义域名上 Cloudflare 会自动注入它自己的 Web Analytics 脚本，不属于游戏文件）。
内联的素材只有豆包的头：一张官方头像和一张由图生 3D 模型采样出来的头部形状图，合计约 105 KB；
她的身体、自行车，以及城市里的材质、建筑、植被、车辆、音效和配乐全部由代码现场算出来。

> 我需要你派出多个 Agent 继续 review 一下 我需要真实的豆包贴图模型 继续迭代：我允许你使用外部的模型和贴图资源 我需要官方版豆包的长相，而不是你生成的这个完全不像的东西
> 迭代完成直接上线

> 人物建模不够精细 继续优化

对应的四次转向：

1. 去另一个终端 Tab 读了对一款单文件 3D 射击游戏的技术拆解，把原计划的手写 WebGL2 渲染器改成同一条路线：Three.js 做底座，画面质感靠 PBR 光照与自建后处理链。
2. 场景从色块玩具风重做成写实街区（程序化 PBR 材质、带室内的建筑立面、枝叶树木、街道设施）；主角的脸改用官方头像，并加了正面镜头。
3. 派出四个子 Agent：一个去找官方 3D 素材，三个分别评审相似度、场景写实度和代码。结论是官方没有公开的 3D 模型，于是用官方头像做图生 3D 得到头部模型，再把官方原图投影到正面。
4. 人物重做：头不再直接用生成模型那张坑洼的三角网，而是把它的形状重新采样成规整光滑的网格，头发改成程序化的发丝；身体从几段胶囊换成一张连续蒙皮的网格，手有了手指，真正握住车把和枪柄。

## 豆包的形象是怎么来的

- **官方素材**：豆包 App Store 图标（1024×1024 正面头像）。调研过官网的 2136 个脚本分包，没有任何 3D 模型、Spine、Live2D 之类的素材，也没有官方的全身或背面图。
- **头的形状**：把这张图标交给图生 3D 模型 TRELLIS（Hugging Face 上的公开 Space）生成带贴图的胸像。生成的三角网表面坑洼、布线杂乱、侧后方贴图发花，所以只取它的形状：`tools/prep-head.mjs` 从头部中轴向外发射射线，把最外层表面记成一张 288×89 的半径图（上半是半球、下半是圆柱的参数化），按贴图颜色分出头发和皮肤，两个区域各自平滑，再把每一列的下沿对齐到发梢或下颌线。存下来只有 77 KB。
- **头的网格**：运行时由半径图重建出布线规整的光滑网格（约 5.7 万三角形），再加上三十多束宽窄不一的发束起伏、长短参差的发梢、封实并压暗的头发底面和一截脖子。
- **脸**：正面按剪影对齐（重合度 0.96）后把官方原图沿视线方向投影上去，所以从正面看就是官方那张脸。投影只落在从正面看得见的那层表面上（启动时沿投影方向做一张深度图来判断），耳朵后面的头发、鬓发挡住的脸颊不会也印上一份。
- **头发**：侧面和后脑不用贴图，颜色是沿发流方向拉长的噪声（一丝一丝的深浅），高光按发丝切线计算（Kajiya-Kay），所以光泽是横跨发丝的一条带子。发流从头顶偏左的发缝向两侧梳开，到侧面和后脑变成垂直向下。
- **眨眼**：在官方图的眼睛位置上，用肤色自上而下盖住眼睛、边缘画一条睫毛线。每隔几秒眨一下，挨打时闭眼。
- **身体**：官方只有半身像，所以身体是按它建的：黑色圆领 T 恤、白色内领口、与头相称的肩宽；下半身（牛仔短裤、白袜、蓝白球鞋）没有官方依据，是自己配的。整个身体是一张约 2.9 万三角形的连续网格，每帧在 CPU 上变形：躯干沿脊柱逐段前倾和扭转，肘和膝按关节角度逐顶点弯曲。手有手掌、四指和拇指，手指沿着被握物体的圆弧弯曲；手腕的位置由车把和枪柄反推，所以手是真的握在上面。
- **看得到脸**：左上角有一个实时的正面镜头；开场、选强化和倒地时镜头会绕到正面；击杀后她会回头看一眼。

## 玩法

- 豆包骑车的方向相对镜头：朝哪看、往哪骑；按住「后」是朝镜头骑，可以一边逃一边回头射击
- 四把玩具爆能枪：豆豆冲锋枪、爆米花霰弹枪、深度思考磁轨炮（穿透）、灵感火箭筒（范围爆炸，离爆点近可以火箭跳）
- 车铃冲击波：震退周围敌人并清掉弹幕；深度思考：子弹时间
- 道路跳台、滑板公园起跳台、可以骑上去的平台、货柜和车顶；腾空击杀、单车冲撞、连杀都有额外加分
- 六种敌人：成群扑咬的 Bug、会预判射击的乱码兵、盘旋的弹窗无人机、追着你跑的独轮骑手、正面带护盾的防火墙，每 5 波出现 Boss「幻觉之王」（环形弹幕、追踪导弹、可以跳过去的贴地扫射激光、召唤 Bug）
- 每清完一波三选一强化，共 13 种，可叠加
- 昼夜循环：白天、黄昏、夜晚的光照、天空、窗灯和路灯都会变化

## 技术

| 方面 | 做法 |
| --- | --- |
| 渲染底座 | Three.js r186（esbuild 摇树后打包内联），关闭内置抗锯齿，改用渲染目标上的 MSAA |
| 材质库 | 13 种程序化 PBR 材质（沥青、混凝土、红砖、涂料、面包砖、瓦楞钢板、金属板、木板、树皮、屋面、花岗岩、瓷砖、土壤）启动时在 GPU 上烘焙进两个纹理数组：反照率 + 高度、粗糙度 + AO + 金属度，全部四方连续 |
| 物体材质 | 标准 PBR 材质 + `onBeforeCompile` 注入：按顶点里的材质层做盒式 / 柱面投影采样，凹凸法线由高度的屏幕空间差分得到，另有自发光、数字溶解和解析式路灯光池 |
| 建筑立面 | 一个着色器算出窗洞、窗框、窗棂、窗台、楼层线、雨水污渍；窗内是室内视差（视线与虚拟房间盒求交），有家具色块、货架、窗帘和百叶；夜里按楼栋类型决定亮灯比例，亮度和色温逐窗不同 |
| 地面 | 一个着色器按世界坐标选材质层，再叠加标线磨损、沥青补丁与裂缝、蓝色自行车道、斑马线、井盖、路缘积水和湿痕、广场石板、草地 |
| 模型 | 建筑、阳台、空调外机、雨棚、汽车、红绿灯、公交站、路灯、货柜等全部由基础几何体拼装烘焙；树是程序化枝干 + 透明测试的叶片卡片（叶片图集用 Canvas 2D 现画），草是按相机位置循环铺设的实例化草丛 |
| 豆包 | 头部是图生 3D 模型的形状 + 官方原图正面投影 + 程序化发丝；身体是程序化建模的连续蒙皮网格（见上一节）。姿态由两段 IK 实时求解：腿踩踏板、左手握把、右手持枪指向准星，躯干和头随瞄准方向扭转 |
| 光照 | PCF 软阴影（跟随玩家并按纹素对齐）、PMREM 环境反射随昼夜重新卷积、6 盏点光源池（枪口、爆炸、弹幕） |
| 剔除 | 静态几何和枝叶按 40 米的格子、地形按 64 米一块分别成网格，主视角、阴影、正面镜头三个通道各自做视锥剔除；相机附近没有草地时整批草丛不提交 |
| 后处理 | 自建链路：半分辨率 AO + 阴影贴图步进体积光 → 双边模糊 → 相机运动模糊 → 双滤波 Bloom → 镜头光晕 → 自动曝光 → ACES → FXAA；左上角的正面镜头是把场景按小窗的实际像素尺寸再渲染一遍（隔帧更新）后在合成阶段画进去的 |
| 环境动画 | 红绿灯变灯、喷泉、落樱、飞鸟、被车轮压弯的草、随风摆动的枝叶 |
| 音频 | 纯 Web Audio 合成：音效、卷积混响的脉冲响应、3D 声像、16 步音序器配乐（按战斗强度叠加声部） |
| 物理 | 自写：高度场地形 + 人行道 + 坡道 + 可骑平台，圆 / OBB 碰撞滑移，射线检测 |
| 画质 | 低 / 中 / 高 / 极致四档 + 自动（帧率持续偏低时逐级下调）；低档关闭草丛、AO、体积光和正面镜头 |
| 输入 | 键鼠（Pointer Lock，失败时降级）、触屏虚拟摇杆、标准手柄 |

## 本地构建

```bash
npm install        # three、esbuild，以及只在处理头模时用到的 sharp
node build.mjs     # 产物输出到 dist/index.html，浏览器直接打开即可
node build.mjs --dev   # 不压缩，便于调试
```

`assets/` 里是已经处理好的素材，正常构建不需要重新生成。要从一个新的 GLB 重做头模：
`node tools/prep-head.mjs <胸像.glb> [--debug <目录>]`（脸朝 +Z、Y 向上、带内嵌贴图；`--debug` 会导出半径图、分区图和法线预览）。
图生 3D 得到的原始 GLB 有 1.8 MB，没有放进仓库。

调试用 URL 参数：`?q=low|medium|high|ultra` 指定画质，`?seed=` 世界种子，`?tod=0..1` 固定时刻，
`?start` 跳过菜单，`?auto` 自动驾驶，`?god` 无敌，`?wave=N` 从第 N 波开始，`?spawn=0,1,5` 指定生成的敌人，
`?headcam=角度,距离,高度[,注视点上移,视角,注视点前移,注视点左移]` 让镜头绕着豆包看，`?blink=0..1` 固定眨眼程度。
控制台里有 `__G`（游戏状态）、`__stats()`、`__sim(秒)`（不渲染快进模拟）、`__errors`。

## 自测

全部在无头 Chromium（SwiftShader 软件渲染）里完成，没有真机和真实显卡上的测试：

- 人物从正面、3/4 侧、正侧、背面、俯视、仰视逐角度截图，对照官方头像检查了头、领口、双手握把与握枪、鞋；另外检查了向左、向右、向后瞄准，冲刺，眨眼，受击闪白，以及夜晚和低画质下的样子；截图检查了白天 / 黄昏 / 夜晚的城区、公园、货柜场、公交站，以及主菜单、强化选择、手机横屏布局
- 相似度、写实度、代码三个评审子 Agent 各给了一份按严重程度排序的问题清单（写实度一项拍了 90 多张对照图），大部分已处理并复查，没做的列在下面
- 代码评审查出并已修复的问题：凹凸法线在细长三角形上算出 NaN 造成的画面黑点、人行道端头把车弹飞 6 米、按数字键选强化会同时切枪、低速骑出起跳台或平台边缘会瞬移到地面、选强化时补给继续过期、镜头没转回身后就能开火、切画质泄漏材质纹理、草丛高度取样偏半个纹素
- 脚本化输入验证单车物理：平地极速 13.2 m/s、冲刺 18.7 m/s；道路跳台巡航起跳最高 1.75 m、冲刺 2.2 m，大起跳台 3.4 m；撞墙、撞货柜、场地边界均不穿透
- 自动驾驶 + 无敌快进 10 分钟模拟时间，到第 18 波、击杀 277，无报错
- 自动驾驶不开无敌的几局：止步第 5 到第 9 波，或 5 分钟时仍存活在第 9 到 11 波（这个 bot 不会躲弹幕）
- 运行时切换五档画质、触发窗口缩放，无报错

没有验证的部分：真实设备上的帧率——场景比第一版重得多，高画质下每帧约 120 到 230 次绘制、60 到 140 万三角形（含阴影和左上角的正面镜头；其中人物约 8.6 万三角形，三个通道各画一遍）；身体蒙皮在本机 Node 里每帧约 0.35 毫秒，手机上没有测过；手柄输入只做了代码检查；音效和配乐只确认了不报错；WebGL 上下文丢失后的恢复是评审在无头环境里验证的，真机没试过。

评审里提了但这一版没做的：

- 街块仍然是独栋楼加空地，没有沿街连续的裙楼；公园里没有园路和亭子
- 汽车只加了轮拱和反光车窗，车身还是方盒造型；货柜没有角件和箱号；底商没有做门
- 阴影只覆盖玩家周围 46 米，更远的树和楼没有落影
- 镜头贴近树冠或草丛时叶片会贴脸
- 豆包的脸是一张静止的官方原图，除了眨眼没有别的表情，嘴不会动；头的形状来自图生 3D，后脑和她右侧是模型补出来的，不是官方设计
- 手腕是一个球形关节，手和前臂的夹角大时看得出接缝；T 恤和短裤没有随动作变化的褶皱
- 低画质档每个像素仍然要算 6 盏点光源和 4 次材质采样；树叶的影子不跟着风摆动
- 着色器里用常量数组加动态下标取材质平铺尺度，在老安卓驱动上的表现没法确认
